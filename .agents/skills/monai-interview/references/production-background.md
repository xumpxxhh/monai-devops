# 固定模拟生产背景 v1

性质：用户授权的面试练习设定，非真实上线证据。用户确认 CI/CD 交付平台、七人团队、约百名使用者、本人以校招生身份加入，参与一年多，承担全栈及项目关键模块开发。以下业务、日期、规模、架构、事故均为固定的合理模拟补齐，不改变仓库现实。

## 人员、定位和规模

公司业务是工业互联网，产品包括采集工业现场数据的边缘网关，以及汇聚网关等来源的数据并提供分析、告警的工业数据智能平台。monai-devops 是支撑这些产品研发交付的内部 CI/CD 平台，重点服务网关管理相关后端服务和工业数据智能平台服务的构建、测试与发布，整合 GitLab 源码、Harbor 镜像和 Kubernetes 部署，统一模板、审批、跨服务编排与运行追溯。它不负责现场数据采集或分析告警业务逻辑；模拟范围不包含网关固件 OTA、设备侧灰度或边缘节点远程升级。不支持外部 Fork、不做公共 SaaS，不承诺全面替代 GitLab CI。

七人：技术负责人一名，研发三名（我和两名同事），测试一名，运维一名，产品一名。我负责编排内核、执行协议与可靠性、编辑器和运行详情中的核心实现，参与方案讨论并在技术负责人评审下落地；其他研发负责部分插件、触发、审批模块，运维负责基础设施，测试负责集成及异常验证，技术负责人负责评审。不能说一个人包办所有成果。

模拟时间：2025 年 7 月以校招生身份加入项目，参与至 2026 年 10 月，约一年三个月；2026 年 6 月两个团队试点，8 月正式内部上线，观察点 2026-10-14。团队在我加入前已启动基础建设。仓库提交和迁移日期不是模拟日期的证据。

约 100 名已开通用户，工作日约 30—40 名实际使用者，8 个研发团队、约 35 个服务仓库。普通工作日约 150 次 Run，集中发布日约 300 次。典型工作流 6—10 个逻辑步骤，构建约 5—15 分钟。没有完整 P95 统计或性能提升百分比。

构建池 6 台 Linux 主机，每台 8 核 16 GB，各运行最多两个构建容器，总构建容量 12。实际繁忙时段约 8—10 个构建并行。发布使用独立受控执行池。100 名用户不是 100 并发，容量上限不是压测极限；没有万级 QPS 或跨地域双活经历。

## 交付场景

网关管理服务和工业数据智能平台的后端服务原来分别采用 GitLab CI 配置和人工发布脚本，模板和凭据分散，发版依赖关系与审批记录不易统一追溯。平台不是因为其他产品“不支持 DAG”而自研，而是统一企业交付规则与跨服务流程，继续复用 GitLab、Harbor、Kubernetes，承担自研协议和运维成本。

GitLab Webhook 校验共享密钥和来源，按项目与事件 ID 去重，解析 commit SHA，冻结模板版本和工作流快照，创建 Run；触发接口不直接同步运行构建。重跑创建新 Run，保留原始提交与模板版本，记录操作者和来源。

匿名示例 alert-service 为工业数据智能平台的告警服务（Node）：checkout 指定 SHA，锁文件安装，lint 与测试按依赖并行，build，构建镜像，推送 Harbor，用 digest 部署测试环境，健康检查，人工审批，生产部署与验证。feature 分支仅构建测试，main 合入跑完整测试链路。Java 服务有独立模板，不声称支持所有语言。

生产审批绑定 commit、不可变 digest、目标环境，变更输入或产物重新审批。生产部署必须有审批。回滚到上一次确认健康的 digest，不重新构建旧源码。数据库采用前后兼容的分阶段迁移，没有一键数据库回滚。

## 固定生产扩展架构

React 控制台、NestJS API、TypeScript 编排、PostgreSQL 权威状态。单地域企业 Kubernetes，API 两副本，Run 与 Attempt 所有权用数据库租约。Worker 通过 HTTP 拉取与回传；事务、SKIP LOCKED、条件更新协调，不依赖内存锁。没有 Redis、Kafka、RabbitMQ、BullMQ；该规模下控制中间件运维成本，代价是轮询、索引和历史清理压力。

生产补齐的 checkout/build/publish/deploy 插件在 Runner 启动一次性 Docker 容器，独立工作区、默认非 root、CPU/内存/时间限制及清理。API 不执行构建脚本。Docker socket 不直接暴露给任意仓库脚本，镜像构建使用受控入口；构建池不持有生产集群凭据，发布池独立。只面向可信内部仓库，不声称容器可安全执行任意恶意代码。

缓存为 Runner 本地可丢弃缓存，键包含项目、运行时版本和锁文件摘要，不保证跨主机命中，没有统计命中率。

Harbor 存镜像，MinIO 存大日志、报告和制品，数据库存元数据、校验和与生命周期事件。日志按分片和 offset 读取，不逐行写 RunEvent。普通日志留 30 天，发布和审批元数据 180 天；发布镜像保留最近 10 个已发布版本，当前和回滚引用受保护。这是模拟生产扩展，非当前数据库 Bytes 的 ExecutorObject 实现。

网关接企业 OIDC，服务端校验身份及项目成员、编辑、执行、审批权限，WS 订阅检查 Run 所属项目。不是只靠网关认证保护所有对象。Worker 独立服务身份和能力白名单，不用人类登录 Token。单企业多项目，不是商业多租户 SaaS。

运维管理 Kubernetes Secret，按项目/环境给受控执行池授权。工作流只存引用，快照无明文；按已注入密钥脱敏日志，不保证识别任意变换内容。没有 Vault 或动态云身份。

审批和环境锁是模拟领域扩展，不把 execution.wait 等同完整审批产品。锁键为项目/服务/环境，数据库保存所有权和租约；相同服务环境不得同时发布。所有权丢失不继续提交部署，不确定的结果先查 Kubernetes revision/digest，不能盲重试。

单地域托管 PostgreSQL 主备，运维维护日备份与 WAL，不是自研数据库 HA。Prometheus/Grafana 观察 API、队列、失败率、Runner 使用；现有告警渠道通知值班。没有全链路 OpenTelemetry 或服务网格。目标 API 月度可用性 99.9%，RPO 15 分钟、RTO 1 小时，未通过完整灾备演练，不声称实测达成。

## 执行语义

Run 是整次流水线，Job 是逻辑步骤，Attempt 是单次执行。工作流快照隔离后续编辑。Worker 消息带 attemptId、leaseToken、单调序号，过期租约不得覆盖新结果，重复回传通过接收记录和状态推进事务去重。外部副作用不保证 exactly-once。

Run 调度并发、步骤并行、构建池容量、环境锁是不同约束。跨进程配额依赖持久化所有权，内核内存槽位不自动构成分布式信号量。队列等待形成背压，API 不等待全流程。

明确 retryable 的基础设施故障最多三次 Attempt，指数退避。测试失败、配置错误、权限拒绝、取消不自动重试。发布结果不确定时先核验环境。心跳、租约具体秒数未固定，不把源码默认值猜成生产配置。

重启恢复数据库里的待调度和等待状态，复用已完成结果；活跃 Attempt 结合租约/回传判定。Worker 失联后的可重试构建重新执行，不恢复 npm 进程内存。暂停阻止后续调度；取消先协作处理，可终止构建容器，但不能保证撤销已提交的外部部署请求。

前端 REST 读取 Run 快照及有序历史事件，归约后记录最后连续处理的 eventIndex，再从下一条订阅 WS 增量。断线自动重连时携带该游标请求补发。相同或更小 eventIndex 丢弃；收到跳号事件先短暂缓冲并补取缺口，按顺序归约，不把乱序事件直接写入状态树。若游标已超出可回放范围或重连期间状态不能连续恢复，则重新获取服务端权威 Run 状态和可用事件并重建页面；终态以服务端持久化结果校准。前端不是权威状态，WS 不是可靠任务总线。

## 固定模拟经历

事故一：8 月试点扩展，一台 Worker 主机重启，alert-service 已推送镜像但完成消息未确认。通过 Run/Attempt 和 Harbor digest 核验，不把不确定产物直接送生产；重新构建并重新审批，这次发布延后约 20 分钟，无线上服务中断。后续交付输入绑定不可变 digest，区分可重试构建和不可盲重试发布。我负责执行状态与发布输入约束，同事配合插件，运维定位主机问题。不是用“幂等”万能解决。

问题二：6 月试点运行详情 WS 断线，漏掉完成事件，后端已完成但页面仍运行中。重连仅订阅实时消息未补历史。修为快照和历史加载、eventIndex 去重及断线补齐，验证重复和断线场景。属于试点缺陷，无服务停机，没有提升百分比。

演练三：上线前在测试环境注入 API 重启、Worker 断线、重复回传，验证旧租约拒绝、去重和状态收敛。不是生产事故，不是整体机房或数据库灾备演练。

只使用这些固定经历。没有 Kafka 堆积、Redis 雪崩、数据库宕机、密钥泄露、千万级压测或跨地域切换亲历。被问其他事故直接说没有遇到，再解释实际机制，不能新编事故。

## 没有做的能力

没有公共插件市场、任意插件在线上传执行、供应链签名治理、不可信代码认证、Pipeline as Code 双向同步、复杂动态矩阵、多云、跨地域双活、自动金丝雀分析。发布是滚动更新和健康检查，回滚 digest。没有准确成本节省额、全年可用性报表、P95、极限压测结论。后续方向不能说已上线。
